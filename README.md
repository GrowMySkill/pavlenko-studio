# Студия красоты Натальи Павленко

Одностраничный сайт с заявками на запись для двух филиалов в Новороссийске. Стек — Next.js App Router, TypeScript, Tailwind CSS и Zod.

## Запуск

Требуется Node.js 20.9+ и npm. Сборка загружает Cormorant Garamond и Manrope из Google Fonts через `next/font` и отдаёт шрифты с самого сайта.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Локальная страница доступна на http://localhost:3000. Проверка production-сборки:

```bash
npm run lint
npm run build
npm run start
```

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `MAX_BOT_TOKEN` | Токен бота MAX, передаётся только сервером. |
| `MAX_RECIPIENT_ID` | Числовой `user_id` получателя в личном диалоге с ботом. Откройте диалог с ботом и проверьте доставку тестовой заявки. |
| `NODE_EXTRA_CA_CERTS` | Если среда не доверяет цепочке сертификата MAX, укажите при запуске Node путь к доверенному PEM согласно документации MAX. |
| `BOOKING_DATA_DIR` | Необязательный путь к каталогу заявок. По умолчанию `.data/bookings/`. |
| `BOOKING_IP_HEADER` | Имя заголовка с одним IP, который доверенный прокси перезаписывает, например `x-real-ip`. Без настроенного заголовка используется общий локальный лимит. |
| `NEXT_PUBLIC_YM_ID` | Числовой ID счётчика Метрики. Устанавливается до сборки. Пустое значение отключает счётчик. |

Создайте в Метрике цели типа «Целевое событие» с ID `phone_click`, `whatsapp_click`, `telegram_click` и `booking_submit`. Последняя срабатывает после успешного сохранения заявки. В события не передаются поля формы.

## Контент и изображения

Все сведения о студии находятся в [content/studio.json](content/studio.json). После редактирования пересоберите сайт.

- `branches` — отдельная запись на филиал. В `hours` задавайте группы дней с часами в формате `HH:MM`. Дни идут от `0` (воскресенье) до `6` (суббота). Для перерыва задайте две группы с теми же днями. Даты и слоты считаются по `timezone`.
- `categories[].items` — услуги со стабильным уникальным `id`, названием, ценой в рублях и списком `branchIds`. Укажите `null` для неизвестной цены. Услуга появляется в форме для перечисленных филиалов.
- `masters` — уникальный `id`, имя, специализация, фото и список филиалов. Пустой `serviceIds` означает, что мастер доступен для любой услуги своего филиала.
- `images` — фото первого экрана и галерея. Положите JPG, PNG, WebP или AVIF в `public/images` и укажите путь вида `/images/hero.webp` и осмысленный `alt`. Без списка галереи используются свободные файлы из корня этого каталога.
- `reviews` — автор, дословный текст, `rating` (на сайте показываются только оценки 5 из 5), `date` в формате `YYYY-MM-DD`, `source` (`yandex` или `2gis`), `branchId` и `url`. Если `url` пуст, используется вкладка отзывов из `links.reviews`. Скриншоты из `public/images/reviews` отображаются автоматически. Для скриншота при конкретном отзыве укажите его путь и `alt` в поле `image`.
- `ratingSummary` — рейтинг и количество оценок каждой карточки. `links` хранит адрес ВКонтакте и адреса вкладок отзывов.
- [content/images-sources.json](content/images-sources.json) — источники добавленных фотографий.
- `seo` — необязательные переопределения заголовка и описания, а также полный адрес сайта в `siteUrl`. Без переопределений заголовок и описание собираются из данных студии. Адрес сайта нужен для канонической ссылки и изображения Open Graph.
- `privacy.text` — текст политики, на странице сохраняются переводы строк.

Данные о контактах, графике и услугах сверены с карточками [Южная, 9](https://2gis.ru/novorossiysk/firm/70000001061953746), [Пионерская, 25](https://2gis.ru/novorossiysk/firm/70000001033112530) и предоставленной [карточкой Яндекс Карт](https://yandex.ru/maps/org/studiya_krasoty_natalyi_pavlenko/235694714970/). Дублирующаяся строка длинной укладки в прайсе показана один раз.

## Заявки

`POST /api/booking` проверяет данные, согласие, поле-ловушку, доступность услуги и мастера в филиале, дату и время. Время из рабочего графика обозначает желаемый получасовой слот. Запись подтверждает администратор.

Лимит — пять запросов за десять минут на IP в рамках одного процесса. Для нескольких инстансов используйте общий лимитер и прокси, который сам выставляет IP. При запуске в интернете ограничьте размер тела запроса на прокси.

`BookingStore` по умолчанию записывает каждую заявку отдельным файлом вне `public`. На Vercel каталог приложения доступен только для чтения, а `/tmp` временный. Для размещения на Vercel подключите постоянную БД или Google Sheets через реализацию `BookingStore`.

Сервер сохраняет заявку перед отправкой в MAX. Если доставка не удалась, клиент всё равно видит успех, а сервер пишет идентификатор заявки и причину ошибки без полей заявки. Первая строка сообщения содержит данные в запрошенном формате, вторая — выбранный филиал. API сверено с [документацией MAX](https://dev.max.ru/docs-api/methods/POST/messages).

## GitHub Pages

В настройках репозитория откройте **Settings → Pages** и выберите **GitHub Actions** в поле **Source**. Workflow `Publish GitHub Pages` собирает сайт при обновлении `main`. Первый запуск можно запустить вручную во вкладке **Actions**.

На GitHub Pages публикуется демоверсия. Форму можно заполнить, а отправка отключена. Для приёма заявок используйте обычную сборку Next.js на хостинге с серверным обработчиком `/api/booking`.
